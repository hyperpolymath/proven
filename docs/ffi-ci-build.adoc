== FFI CI build: explicit profiles and the repo-local RefC bridge

The header bridge uses Idris2 commit
`b6cbc25d5cd2ef2a250556266fd7b68dfc360f8b`, its matching RefC SDK,
Zig 0.15.2 and native Linux x86_64 GNU. The declared private
`language-bridges` dependency had no production callers and has been removed.
Actual ABI marshaling lives in `ffi/zig/src/refc/`. No private checkout or
`LANGUAGE_BRIDGES_TOKEN` is needed, including for fork pull requests.

[cols="1,2,2",options="header"]
|===
|Build entry |Inputs |Result
|`ffi/zig/build.zig`
|Fresh C from `proven-ffi.ipkg` plus all four SDK/source path options
|`libproven.a`; the declared FFI package and its import cone are built
|`ffi/zig/build_standalone.zig` without `-Dheader-refc`
|Zig only
|Legacy ABI surface; header operations explicitly return -99
|`ffi/zig/build_standalone.zig` with `-Dheader-refc`
|Completed native header bundle from `scripts/build-header-refc.sh`
|Actual Idris header backend; static library or `-Dshared=true` shared library
|===

Other legacy exports are outside the header proof qualification. Full-package
build success does not establish that every public C declaration is available
or that all source/compiler refinement obligations are discharged.

=== Header profile

From the repository root, with the pinned tools on PATH:

[source,bash]
----
bash scripts/test-header-bridge.sh
----

This executes the real generated Idris function, the exported Zig ABI and a
caller compiled against the public C header. It checks all single bytes and
pairs, NUL, non-UTF-8, null/empty and length boundaries, and rejects a wrong
backend. Failed-producer controls also prove that old bundles cannot rescue
a failed rebuild. The builder invalidates its previous artifacts before any
tool checks, and the Zig build refuses a missing or non-PASS completion marker.
The marker is build state, not an Atoma proof certificate.

For a shared library, choose a dedicated absolute bundle/output path:

[source,bash]
----
bash scripts/build-header-refc.sh "$PWD/build/header-refc"
bundle="$PWD/build/header-refc"
(cd ffi/zig; zig build --build-file build_standalone.zig -Dshared=true -Dheader-refc="$bundle")
----

Use one producer per bundle directory. To rebuild an old bundle predating the
completion marker, run the builder again; do not fabricate a marker.

=== Full FFI package pipeline

The generator copies the Idris sources and package into a clean scratch tree.
It enables totality and warnings-as-errors through `proven-ffi.ipkg`, requires
one fresh C translation unit and the reachable header symbol, and records
matching SDK paths in `build/refc/sdk.env`. It never collects arbitrary C files
from an existing build tree.

[source,bash]
----
bash scripts/build-refc.sh --verbose
source build/refc/sdk.env
(cd ffi/zig; zig build \
  -Didris-refc="$REFC_OUTPUT_DIR" \
  -Didris-refc-runtime="$IDRIS2_REFC_RUNTIME" \
  -Didris-c-support="$IDRIS2_C_SUPPORT" \
  -Didris-support-lib="$IDRIS2_SUPPORT_LIB")
(cd ffi/zig; zig build test \
  -Didris-refc="$REFC_OUTPUT_DIR" \
  -Didris-refc-runtime="$IDRIS2_REFC_RUNTIME" \
  -Didris-c-support="$IDRIS2_C_SUPPORT" \
  -Didris-support-lib="$IDRIS2_SUPPORT_LIB")
bash scripts/test-refc-staging.sh
----

The runtime also requires libc, libgmp, pthread and libm. The existing
`.github/workflows/ffi-full-integration.yml` runs this path without secrets,
including on fork PRs. It uploads the generated-source/SDK identity, build
logs and stale-output rejection results. An actual failure remains a failure;
there is no credential-based success-by-skipping path.

=== Consumers and proof replay

Chapel, D and OCaml producers sparse-check out their explicit source/script
inputs, build the real shared library and pass it to detached consumer jobs.
OCaml's `proven.wired` module exercises the five available symbols; the separate
full-API gate still exposes its unresolved lifecycle mismatch. See
link:adr/0001-binding-ci-template.adoc[the producer/consumer contract].

Broad E2E, cross-target and fuzzing jobs using the unavailable profile qualify
only the legacy operations they actually call. They do not establish a working
Idris header backend. The separate `header-refc.yml` and `header-theory.yml`
gates cover executable evidence and Agda/Cubical/Lean/Rocq replay respectively.
See link:adr/2026-11-16-header-refc-boundary.adoc[the header boundary decision]
for exact qualification and open source/compiler refinement obligations.
