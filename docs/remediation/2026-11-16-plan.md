# Proven: prioritized remediation plan

Date: 2026-11-16. Baseline: `c13619f9a67a1b9e8234e22e22dae0940d2480cb`.
Working branch: `fix/critical-proof-remediation-20261116`.

Current batch: lifecycle ABI source, proof bodies and native regression fixtures
are drafted, **not validated**, while waiting for BotMania's heavy-work slot.
See `2026-11-16-native-abi-draft.md`. Prior PASS results apply to the preceding
nonce/entropy snapshot; they do not establish the new native changes.

The audit found demonstrably false acceptance paths, incomplete implementations,
claims whose propositions do not express the advertised property, and gaps between
Idris proofs and delivered native code. Fix false acceptance first; establish the
native execution path before extending end-to-end assurance claims.

This plan covers all 25 findings from the 2026-11-15 audit. The accompanying
`proof-worklist-20261115.csv` preserves the 374 baseline review entries. These
are review tasks, not 374 confirmed vulnerabilities or 374 independent theorems.
Line numbers and statuses in that snapshot refer to the baseline; they are not
automatically discharged by this change.

## Completion rules

Every remediation needs a precise production behavior, a meaningful proposition
about that behavior, a total checked proof with its assumptions identified, and
executable positive/negative regressions that fail on the buggy implementation.
Unsupported operations must return an explicit failure. An OWED declaration,
Unit-valued claim, assertion of totality, simulated backend, or compilation alone
does not satisfy these criteria.

Core logic remains in Idris. Zig supplies ABI glue. Generated/native code needs
separate linkage, lifetime, encoding, layout, and behavioral checks. Formal
functional correctness does not establish cryptographic hardness, compiler
correctness, constant-time machine execution, OS entropy, or protocol security.

Statuses: **implemented** is a change present on this branch; **contained** is
an unsafe path disabled while its real implementation remains absent;
**partial** closes only the stated subproblem; **pending** has not been fixed.
Validation evidence is recorded in `2026-11-16-validation.md` (first batch) and
`2026-11-16-jwt-sql.md` (JWT/SQL batch), and
`2026-11-16-native-nonce.md` (current bridge, nonce and entropy evidence).

## Changes in this first batch

- F01/F02: add `ECHIDNA.Kernel`; route `validateProof` and
  `validateComprehensive` through it; replace the vacuous Soundness module.
  The old arbitrary-backend/consensus abstractions are intentionally removed:
  their types provided no established semantic guarantee. No in-repository
  callers used them. This is an API compatibility change for external consumers.
  Legacy `infer`/`check`/`validateWellFormed` remain syntax diagnostics only;
  `validateWellFormed` now has a distinct `WellFormedResult` type. Use the
  certificate API or goal-specific validator for proof certification.
- F03 containment: disable the permissive signature check, preserve replay state,
  and require evidence of actual accepted execution to construct
  `WebhookVerified`. This changes behavior to explicit unavailability and changes
  the evidence type's parameters. It does not implement HMAC or Ed25519.
- F05 comparator subproblem: replace byte truncation with a full-character
  comparator, prove its accepted-result fidelity and equal-input acceptance,
  and retain the historical function name with an explicit timing limitation.
- Add source-only fresh compilation, runtime regression assertions, and negative
  compilation fixtures to the existing proof-check job. Build the repaired
  ECHIDNA modules in the main package.
