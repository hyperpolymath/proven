== Claims Substantiation

=== Claim 1: "Safe operations written in Idris2, with dependent types and totality checking." (goal: code that cannot crash)

**How it works:** The core safety modules in `src/Proven/` are written in Idris2, most with `%default total`. A `total` function is checked to (1) terminate and (2) cover all input cases, so it (3) returns a value. **Not every module meets that bar** (measured 2026-11-17, comments excluded): 4 modules use `%default covering` (`SafeJson/Access`, `SafeBase64`, `SafeBase64/Encode`, `SafeRBAC`), 66 functions in 14 files are marked `covering`, and 22 `assert_total`/`assert_smaller` sites in 7 modules (`SafeArgs/Parser`, `SafeInput`, `SafeRegex/Matcher`, `SafeTree`, `SafeUnionFind`, `SafeXML/Parser`, `SafeYAML/Parser`) bypass the totality checker. Those are not totality-proven. Dependent types encode preconditions as types (e.g., `SafeDiv : (a : Nat) -> (b : Nat) -> (h : NonZero b) -> Nat` requires a proof that `b` is nonzero before dividing). The Idris2 compiler enforces these proofs at compile time. Examples: `SafeMath.idr` returns `Maybe`/bounded results instead of overflowing; `SafeString.idr` checks buffer bounds before reading. FFI bindings call these verified functions only—no reimplementation in other languages.

**Caveat:** Verification covers correctness (no crashes, no undefined behavior), not functional correctness (the algorithm might be wrong). Also, Idris2 proved code is only safe if the FFI bridge (`ffi/zig/`) correctly marshals data. If Zig FFI incorrectly casts types or ignores preconditions, safety claims are violated. Hypatia scans report 0 unsafe patterns in critical FFI code; a scan is evidence, not a proof.

**Evidence:** `src/Proven/SafeMath.idr` with `%default total` and dependent type proofs; `src/Proven/SafeString.idr` with bounds-checked buffer operations. FFI in `ffi/zig/src/main.zig` calls verified functions only. `believe_me` count: 0 (eliminated via ADR-008). The test suite did not build at the link:AFFIRMATION.adoc[AFFIRMATION] anchor; see its "What we do NOT claim".

=== Claim 2: "120+ binding targets across 4 computing paradigms without reimplementing logic"

**How it works:** Bindings follow a strict FFI-only pattern (ADR-008 in `.machine_readable/6a2/META.a2ml`). Language-specific bindings (Rust, Zig, Deno, etc.) in `bindings/<lang>/` are thin wrappers that: (1) accept user input in the target language, (2) marshal to C types, (3) call the Zig FFI (`ffi/zig/`), (4) unmarshal results back. No safety logic lives in bindings—only data conversion. This enables many targets without N reimplementations. A breaking change to SafeMath is fixed once in Idris2, recompiled to Zig, and all bindings immediately use the fixed code.

**Caveat:** Bindings are scaffolded — most languages are partially implemented. Incomplete bindings may lack support for all SafeMath operations or all 104 modules. Production focus: Rust, Zig, C first; others are aspirational. Pre-submission hypatia scans enforce 0 HIGH/CRITICAL findings before publishing to opam, crates.io, Hex.pm. Python/Cython bindings were deleted 2026-05-27 in line with the estate-wide Python ban (see `hyperpolymath/standards` language policy).

**Evidence:** `bindings/rust/safe_math.rs` calls proven FFI via `unsafe { proven_ffi_safe_add(...) }`; `bindings/zig/src/safe_math.zig` wraps the same FFI directly; `.machine_readable/6a2/META.a2ml` documents ADR-008; `hypatia-v2 . --severity critical --severity high` confirms 0 findings.
